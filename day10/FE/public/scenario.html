1 · Use case & Nguồn dữ liệu (DB / API / File)

Use case: Một AI Agent (CS + IT Helpdesk, nối tiếp Day 08/09) trả lời nhân viên/khách hàng dựa trên knowledge base. Agent chỉ đúng nếu tầng dữ liệu phía sau publish đúng version hiện hành — không lẫn chính sách cũ (refund 14 ngày, HR 10 ngày phép). Pipeline này là lớp ingest → clean → validate → embed đứng trước agent.

2 · Inject corruption → quan sát qua Freshness / Volume / Log

Cố ý làm hỏng để chứng minh observability bắt được lỗi trước khi agent trả lời sai:

POST /api/v1/pipeline/run
{ "run_id": "inject-bad", "flags": { "no_refund_fix": true, "skip_validate": true } }
Tín hiệu trên Dashboard / LogSạch (run chuẩn)Khi inject
Volume — quarantine_records215215 (nhưng embed chunk "14 ngày")
Validation — expectation8/8 PASSrefund_no_stale_14d_window FAIL
FreshnessFAIL (data cũ 60 ngày)FAIL (không che được lỗi version)
Eval — q_refund_window.hits_forbiddennoyes
Trên Pipeline Runner: node Validation chuyển đỏ + xổ terminal log expectation[refund_no_stale_14d_window] FAIL (halt) :: violations=1. Trên Observability: volume quarantine + freshness phản ánh "sức khỏe" dữ liệu. Đây là cách lỗi lộ ra qua metric, không phải khi user phàn nàn.

3 · Rerun pipeline idempotent → Expectation PASS

Chạy lại pipeline chuẩn. Embed idempotent nên index tự lành mà không nhân đôi vector:

  • Upsert theo chunk_id = sha256(doc_id|chunk_text|seq)[:16] → cùng nội dung ⇒ cùng id, ghi đè thay vì thêm.
  • Prune: xoá id không còn trong cleaned hiện tại ⇒ chunk "14 ngày" bị loại khỏi index (snapshot = publish mới nhất).
POST /api/v1/pipeline/run   { "flags": {} }
expectation[refund_no_stale_14d_window] OK (halt) :: violations=0
expectation[hr_leave_no_stale_10d_annual] OK (halt) :: violations=0
... 8/8 PASS → PIPELINE_OK (exit 0)

Chạy 2 lần liên tiếp cho cùng kết quả (raw=247, cleaned=32, quarantine=215) — đó là tính idempotent.

4 · So sánh câu trả lời Agent Trước / Sau — khớp run_id

Cùng câu hỏi "Khách có bao nhiêu ngày để yêu cầu hoàn tiền?" → context retrieve từ index ở 2 thời điểm:

BEFORE · run_id inject-bad

❌ Agent: "tối đa 14 ngày"

eval eval_inject_bad.csv · q_refund_window hits_forbidden = yes

AFTER · run_id run_2026…

✅ Agent: "tối đa 7 ngày làm việc"

eval after_fix_eval.csv · q_refund_window hits_forbidden = no · grading 10/10

Chuỗi bằng chứng khớp run_id

Mỗi run_id nối liền log → cleaned CSV → quarantine CSV → manifest → vector metadata → eval/grading. Lineage truy vết được:

ArtifactĐường dẫn (theo run_id)
Manifest/api/v1/artifacts/manifests/manifest_<run_id>.json
Quarantine/api/v1/artifacts/quarantine/quarantine_<run_id>.csv
Cleaned/api/v1/artifacts/cleaned/cleaned_<run_id>.csv
Eval / Grading/api/v1/artifacts/eval/grading_run.jsonl
run_id trong manifest == metadata vector embed == file eval ⇒ chứng minh câu trả lời "sau" thực sự đến từ index đã fix, không phải ngẫu nhiên.
